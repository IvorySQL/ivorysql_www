## 背景

单机 PG 面临服务器硬件故障、操作系统崩溃或网络中断，便会导致业务中断，无法持续提供服务。单机架构缺乏高可用机制，无法自动故障转移，恢复依赖人工干预，操作复杂，RTO较长。无法满足业务对连续性、可扩展性、高可靠性及容灾能力的要求。

为了确保 PG 的高可用性并防止宕机，耽误业务的使用，建设强大的PG-HA高可用架构至关重要。Patroni、HAProxy、Keepalived、etcd 等工具可以协同实现HA高可用的这一目标。

## 组件介绍

### Patroni

Patroni 是一个使用 Python 构建的高可用性（HA）PostgreSQL 的方案，Patroni 支持多种分布式配置存储，如 ZooKeeper、etcd、Consul 或 Kubernetes，支持PostgreSQL 9.3 + 以上的版本。

[Patroni 官网地址](https://patroni.readthedocs.io/en/latest/)

### HAProxy

HAProxy 是一款高性能的开源负载均衡器和反向代理器，适用于TCP和HTTP应用程序的连接。HAProxy 能够分配工作负载，能够提升应用程序的性能，表现为缩短响应时间和提高吞吐量。

[ HAProxy 官网介绍](https://www.haproxy.org/)

### Keepalived

Keepalived 提供了负载平衡和高可用性的框架。Keepalived实现了一组健康检查器，根据负载平衡服务器池的健康状况动态自适应地维护和管理负载平衡服务器池。

[Keepalived 官网介绍](https://keepalived.readthedocs.io/en/latest/introduction.html)

### ETCD

ETCD 是一种高度一致的分布式键值存储，提供了一种可靠的方式来存储需要被分布式系统或机器集群访问的数据。它能优雅地处理网络分区中的领导者选举，即使 Leader 节点发生故障也能继续工作。在本方案中，它用于存储 PostgreSQL 高可用集群的状态和配置数据。它被Patroni用来管理集群状态。etcd确保配置数据在集群的所有节点上保持一致。

[ETCD 官网](https://etcd.io/)

### watchdog

Linux 内核看门狗（softdog）。Patroni 定期向 /dev/watchdog 发送心跳，超时未收到时内核强制重启节点，用来防止 Patroni 假死导致双主。

## 防火墙设置

### 防火墙直接关闭

在环境中如果允许关闭防火墙，则是一种最简单的方式。可以使用以下的命令进行关闭。

```bash
-- 关闭防火墙
sudo systemctl stop firewalld

-- 查看防火墙的状态
sudo systemctl status firewalld
```

### 开放指定的端口

如果在实际的环境中，不允许关闭防火墙，只允许放开自定义的端口情况下，需要使用以下的命令进行开放。

#### Patroni 端口配置
- 8008：此端口用于Patroni的HTTP API

```bash
-- 开放8008端口
sudo firewall-cmd --zone=public --add-port=8008/tcp --permanent

-- 重启防火墙使配置生效
sudo firewall-cmd --reload

-- 验证端口是否开放
sudo firewall-cmd --query-port=8008/tcp

```

#### HAProxy 端口配置
- 5000：写端口，只路由到主库（TCP）。
- 5001：读端口，路由到备库（TCP）。

```bash
-- 开放5000端口
sudo firewall-cmd --zone=public --add-port=5000/tcp --permanent

-- 开放5001端口
sudo firewall-cmd --zone=public --add-port=5001/tcp --permanent

-- 重启防火墙使配置生效
sudo firewall-cmd --reload

-- 验证端口是否开放
sudo firewall-cmd --query-port=5000/tcp
sudo firewall-cmd --query-port=5001/tcp
```

#### etcd 端口配置
- 2379：此端口用于etcd客户端通信。
- 2380：此端口用于etcd服务器与服务器之间的通信。

```bash
-- 开放2379端口
sudo firewall-cmd --zone=public --add-port=2379/tcp --permanent

-- 开放2380端口
sudo firewall-cmd --zone=public --add-port=2380/tcp --permanent

-- 重启防火墙使配置生效
sudo firewall-cmd --reload

-- 验证端口是否开放
sudo firewall-cmd --query-port=2379/tcp
sudo firewall-cmd --query-port=2380/tcp
```

#### Keepalived 端口配置

- 112：此端口用于Keepalived实例之间的虚拟路由器冗余协议（VRRP）通信。
- 5405：此端口用于Keepalived实例之间的多播流量。

```bash
# 放行 VRRP 协议
sudo firewall-cmd --permanent --add-rich-rule='rule protocol value="vrrp" accept'
 
# 重载防火墙使配置生效
sudo firewall-cmd --reload
 
# 验证规则是否生效
sudo firewall-cmd --list-rich-rules
```

#### PostgreSQL 端口配置

5432：此端口用于PostgreSQL客户端连接。

```bash
-- 开放5432端口
sudo firewall-cmd --zone=public --add-port=5432/tcp --permanent

-- 重启防火墙使配置生效
sudo firewall-cmd --reload

-- 验证端口是否开放
sudo firewall-cmd --query-port=5432/tcp



```

## 安装 PostgreSQL 17.4

需要在所有的机器上部署PostgreSQL17，仅是安装即可，不需要初始化，Patroni 在启动时会进行初始化实例。

```bash

--  安装编译工具和依赖
sudo yum groupinstall "Development Tools" -y
sudo yum install readline-devel zlib-devel libicu-devel openssl-devel pam-devel libxml2-devel libxslt-devel systemd-devel -y

-- 创建用户和数据目录
sudo groupadd postgres
sudo useradd -g postgres postgres
sudo passwd postgres

sudo useradd -r -s /sbin/nologin etcd
sudo mkdir -p /etc/etcd /var/lib/etcd
sudo chown -R etcd:etcd /var/lib/etcd

-- 创建安装目录
sudo mkdir -p /opt/pgsql
sudo chown postgres:postgres /opt/pgsql
sudo mkdir -p /opt/pgdata17.4
sudo chown postgres:postgres /opt/pgdata17.4

-- PG的源码下载
cd /root
wget https://ftp.postgresql.org/pub/source/v17.4/postgresql-17.4.tar.gz
tar -zxvf postgresql-17.4.tar.gz

-- 进行编译和安装
cd postgresql-17.4
./configure --prefix=/opt/pgsql --with-openssl --with-libxml --with-icu --with-systemd
make -j$(nproc)
sudo make install


# 配置环境变量
echo 'export PATH=/opt/pgsql/bin:$PATH' >> ~/.bash_profile
source ~/.bash_profile
```

```bash
$ cat /etc/systemd/system/etcd.service

Description=etcd
Documentation=https://github.com/etcd-io/etcd
After=network.target

[Service]
Type=notify
User=etcd
ExecStart=/usr/local/bin/etcd --config-file=/etc/etcd/etcd.conf.yml
Restart=on-failure
RestartSec=5
LimitNOFILE=65536

[Install]
WantedBy=multi-user.target
```

## 配置 HAProxy

### 安装 HAProxy
使用以下命令在每台机器上进行安装 `haproxy`

```bash
yum install -y haproxy
```

### 配置HAProxy

在 host01 节点上配置 `haproxy` 的配置文件，然后再传送到 host02 和 host03 节点上。

```bash
-- 备份一份 haproxy 的文件
[root@host01 ~]# cp /etc/haproxy/haproxy.cfg /etc/haproxy/haproxy.cfg--back

-- 把以下内容加入到配置文件中(复制时注意格式问题)
[root@host01 ~]# cat   /etc/haproxy/haproxy.cfg
# /etc/haproxy/haproxy.cfg

global
    log /dev/log local0
    log /dev/log local1 notice
    chroot /var/lib/haproxy
    stats socket /run/haproxy/admin.sock mode 660 level admin
    stats timeout 30s
    user haproxy
    group haproxy
    daemon
    maxconn 1000

defaults
    mode tcp
    log global
    option tcplog
    retries 3
    timeout queue 1m
    timeout connect 4s
    timeout client 60m
    timeout server 60m
    timeout check 5s
    maxconn 900

# ----------------------------
# 监控页面（HTTP）
# ----------------------------
listen stats
    mode http
    bind *:7000
    stats enable
    stats uri /
    stats refresh 10s
    stats admin if TRUE

# ----------------------------
# 写流量：只路由到主库（Patroni /primary 返回 200）
# ----------------------------
listen primary
    bind 192.168.231.140:5000
    mode tcp
    balance first
    option httpchk OPTIONS /primary
    http-check expect status 200
    default-server inter 3s fall 3 rise 2 on-marked-down shutdown-sessions
    server host01      10.0.12.9:5432  maxconn 100 check port 8008
    server host02  10.0.12.4:5432  maxconn 100 check port 8008
    server host03 10.0.16.11:5432 maxconn 100 check port 8008

# ----------------------------
# 读流量：可路由到任意副本
# ----------------------------
listen replicas
    bind 192.168.231.140:5001
    mode tcp
    balance roundrobin
    option httpchk OPTIONS /replica
    http-check expect status 200
    default-server inter 3s fall 3 rise 2 on-marked-down shutdown-sessions
    server host01      10.0.12.9:5432  maxconn 100 check port 8008
    server host02  10.0.12.4:5432  maxconn 100 check port 8008
    server host03 10.0.16.11:5432 maxconn 100 check port 8008

```

### 校验文件的正确性

```bash

```

## 启用 watchdog 

Watchdog 主要用于防止 Patroni 进程假死但未退出的情况，避免节点处于不确定状态。在 Patroni 高可用场景中，当 Patroni 无法正常向 watchdog 发送心跳时，系统会在超时后自动重启节点，从而避免因进程假死导致的脑裂风险。

以下操作需要在每台节点上操作。

### watchdog 安装部署

```bash
-- 使用 yum 源安装 watchdog
sudo yum install -y watchdog

-- 	加载 softdog 内核模块
sudo modprobe softdog
echo "softdog" | sudo tee /etc/modules-load.d/softdog.conf

-- 验证是否有效
$ lsmod | grep softdog
softdog                13319  0


-- watchdog 的权限
echo 'KERNEL=="watchdog", MODE="0600", OWNER="postgres"' | sudo tee /etc/udev/rules.d/99-watchdog.rules
sudo udevadm control --reload-rules
sudo udevadm trigger --subsystem-match=watchdog
sudo chown -R postgres:postgres /dev/watchdog

```

    - host replication replicator 10.0.12.9/32 md5

    - host    postgres        postgres        10.0.12.4/32       trust
    - host    postgres        postgres        10.0.12.9/32       trust
    - host    postgres        postgres        10.0.16.11/32       trust
  initdb:
    - encoding: UTF8
    - data-checksums
    - "auth-host=md5"
    - "auth-local=trust"

  listen: 10.0.12.9:5432

可以在部署的 patroni 节点上运行以下的命令查看运行状态。

```bash
# patronictl -c /etc/patroni.yml list watchdogmycluster
+ Cluster: watchdogmycluster (7585445892328633499) +-------------+-----+------------+-----+
| Member   | Host       | Role    | State     | TL | Receive LSN | Lag | Replay LSN | Lag |
+----------+------------+---------+-----------+----+-------------+-----+------------+-----+
| host01  | 10.0.12.9  | Leader  | running   |  1 |             |     |            |     |
| host02  | 10.0.12.4  | Replica | streaming |  1 |   0/5054D40 |   0 |  0/5054D40 |   0 |
| host03  | 10.0.16.11 | Replica | streaming |  1 |   0/5054D40 |   0 |  0/5054D40 |   0 |
+----------+------------+---------+-----------+----+-------------+-----+------------+-----+
```

| 列名 | 含义 | 说明 |
|:------:|:------:|:------:|
| Member | 成员名称 | 在 patroni.yml 中配置的 name 字段，用于唯一标识该节点 |
|  Host  | 主机地址 | PostgreSQL 监听的 IP |
| Role | 角色 | Leader：当前主库（可读写）<br>Replica：备库（只读，流复制）<br>Sync Standby：同步备库<br>Standby Leader：备用集群中的主节点 |
| State | PostgreSQL 状态 | running:PostgreSQL 正常运行 <br> stopped:PostgreSQL 已停止 <br> starting / restarting：正在启停 <br> streaming:备库正在接收 WAL |
| TL | Timeline（时间线） | PostgreSQL 的 WAL 时间线编号。主库每次 promote 都会增加 TL | 
| Receive LSN | 接收到的 WAL 位置(Log Sequence Number)  | 备库从主库 接收到的最新 WAL 位置 |
| Lag | 接收延迟（Bytes） | 主库当前 LSN - Receive LSN，表示 网络/传输延迟,值越大，说明 WAL 还未完全传到备库。|
| Replay LSN | 已重放的 WAL 位置 | 备库 已应用到数据库的 WAL 位置，可能小于 Receive LSN。|
| Lag | 重放延迟（Bytes） | 主库当前 LSN - Replay LSN ，表示 备库数据落后主库的程度。这是判断能否安全 failover 的关键指标|

> LSN（Log Sequence Number） 是 PostgreSQL WAL 日志的唯一递增标识，格式如 0/5054D40，通过`SELECT pg_wal_lsn_diff('0/6000000', '0/5FFF000')` 计算差值。

## 模拟故障

### 业务持续写入时主库故障

本场景模拟业务持续写入时主库所在主机突然宕机，观察 Patroni 自动故障转移、HAProxy 将写流量切换到新主库，以及业务恢复的过程。当前集群中 host02 为 Leader，host01 和 host03 为 Replica。

#### 创建测试表

通过 VIP 的 5000 端口连接数据库并创建测试表。

```bash
[postgres@host01 ~]$ psql -h 192.168.231.140 -p 5000 -U postgres -d postgres
psql (17.4)
Type "help" for help.

postgres=# create table t(id int);
CREATE TABLE
```

#### 启动持续写入脚本

执行以下脚本，每秒写入一条数据，并输出客户端时间和实际处理写入的数据库节点 IP，同时把输出保存到日志文件中。

```bash
while true;
do
  echo -n "$(date '+%F %T') "
  PGCONNECT_TIMEOUT=3 psql -d postgres -U postgres -h 192.168.231.140 -p 5000 -Atq \
    -c "insert into t values((random()*10)) returning inet_server_addr();" 2>&1
  sleep 1
done | tee /tmp/write_test.log
```

正常写入时输出如下，可以看到写入全部落在当前主库 host02（10.0.12.4）上。

```bash
2026-10-10 20:45:01 10.0.12.4
2026-10-10 20:45:02 10.0.12.4
2026-10-10 20:45:03 10.0.12.4
```

#### 模拟主库故障

保持写入脚本运行，在当前主库 host02 上执行以下命令，模拟主机突然宕机。

```bash
[root@host02 ~]# echo b > /proc/sysrq-trigger
```

> 注意：这个是高危命令，谨慎执行！
